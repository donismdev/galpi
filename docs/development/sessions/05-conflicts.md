# 05회 · 외부 변경·충돌·초안 복구

**작가가 얻는 결과** · 앱과 VS Code가 같은 회차를 고쳐도 작가가 쓴 양쪽 문장을 다시 꺼낼 수 있다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 04회 내장 저장과 03회 외부 편집을 함께 사용한다.

### 구현 순서

1. 디렉터리 감시 이벤트를 변경 힌트로 받고 내용을 다시 읽는다. 외부 편집기의 임시 파일 교체 저장·연속 이벤트·자기 쓰기 이벤트를 지문으로 처리한다. 시작·전면 복귀·수동 새로고침에서 빠진 사건을 재대조한다.
2. 앱 초안이 깨끗하면 외부 원문을 다시 읽고 커서 위치를 가능한 범위에서 보존한다. 수정 중이면 읽은 기준본·내 초안·관측한 디스크 버전을 기록한다. 세 내용을 확인하고 내 초안 / 디스크 / 직접 합치기 중 선택하게 한다.
3. 충돌 선택 전 앱을 꺼도 복구 사본이 남게 한다. 교체 직전 파일이 또 달라지면 새 충돌을 제시한다. 파일 삭제·권한 해제·다른 프로세스 진입도 표현한다. 작품 ID와 문서 ID로 늦은 이벤트를 구별한다.
4. 외부 앱은 잠금 규약을 따르지 않을 수 있으므로 동시 쓰기의 관측 가능한 범위를 보고한다. 미확인 버전에 대한 무조건 덮어쓰기를 호출 경로에서 없앤다.

### 완료 기준

- [ ] **S05.A** · 외부만 수정, 앱만 수정, 양쪽 수정, 외부 재수정, 외부 교체 저장, 외부 삭제를 재현한다.
- [ ] **S05.B** · 충돌 창에서 프로세스 강제 종료 → 재기동 후 두 텍스트가 모두 남고 사용자가 선택 전까지 원본이 유지된다.
- [ ] **S05.C** · A 작품 저장 알림이 늦게 도착한 시점에 B 작품이 열려 있어도 B의 원고는 바뀌지 않는다.

### 추가 지시 (계획 변경분)

원문과 채택 이유는 `docs/development/PLAN_CHANGES.md`에 있다.

- CH1 몫 · 디스크 변경은 프로세스 종료가 아니라 파일 내용(지문)으로 판단한다. ‘충돌 해결 후 저장’은 작업본만 갱신하고 이력·검토 상태를 바꾸지 않는다. CP949 판독 실패 복구 시험(04회 S04.D)을 충돌 흐름에서도 유지한다.

추가 완료 기준

- [ ] **S05.D** · 외부 프로그램을 열었다 닫기만 하면 충돌·변경으로 표시되지 않는다. 외부 수정과 내장 초안을 합쳐 저장해도 커밋 수는 그대로다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 충돌 재현 절차, 복구 사본 경로·보존 시점, 외부 편집기별 확인 결과.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
