# 02회 · 작품 폴더 열기와 안전한 저장 기반

**작가가 얻는 결과** · 빈 폴더로 시작하고 기존 작품을 다시 열어도 작가 파일이 보존된다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 01회 앱 기동과 언어 리소스가 준비되어 있다.

### 구현 순서

1. 폴더 선택 → 새 작품 생성 또는 기존 작품 열기 흐름을 만든다. 무관한 파일이 있는 일반 폴더는 사용자 의도를 확인한 뒤 충돌 없는 이름만 생성한다. 이름 충돌 시 해당 파일과 선택 가능한 다른 폴더를 알려준다.
2. WORKSPACE_FORMAT.md의 작품 manifest, 안정 ID, 버전 검사, 경로 검증, 쓰기 소유권, 임시 쓰기 후 게시·복구를 공통 Rust 경로로 만든다. 취소·읽기 전용·새 버전의 작품을 화면에서 구분한다.
3. 작품 전환 시 이전 작품의 열린 문서와 늦은 이벤트가 새 작품으로 흘러오지 않도록 workspace 세션을 확인한다. 앱의 최근 경로는 기기 데이터에만 둔다.
4. 향후 회차 생성에 쓸 요청 ID와 작업 재시도의 규칙을 문서화한다. 남은 임시 파일 정리가 원본·사용자의 무관한 파일에 영향을 주지 않게 한다.

### 완료 기준

- [ ] **S02.A** · 한글·공백·괄호가 있는 경로에서 생성 → 닫기 → 재열기 후 같은 작품 ID다.
- [ ] **S02.B** · 초기화 중단 후 재실행, 폴더 선택 취소, 읽기 전용, 상위 스키마, 같은 폴더의 동시 열기를 각각 검증한다.
- [ ] **S02.C** · 중요한 무관한 파일과 이름 충돌 파일의 해시가 시도 전후 동일하다. 루트 바깥을 가리키는 경로로 원본을 쓸 수 없다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 작품 열기/닫기 인터페이스, 파일 교체 방식, 실패 코드, 복구 가능한 상태와 테스트 경로.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
