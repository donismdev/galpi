# 03회 · 다음 화 생성과 외부 편집기

**작가가 얻는 결과** · ‘다음 화 쓰기’ 한 번으로 새 원고와 작품 폴더가 VS Code에 열린다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 02회의 실제 작품 세션과 쓰기 경로를 사용한다.

### 구현 순서

1. 다음 번호를 계산하고 회차 메타데이터와 빈 manuscript.md를 한 묶음으로 게시한다. 기존 회차에 결번이 있더라도 최대 번호 뒤에 생성한다. 제목은 나중에 바꿔도 링크 ID는 유지한다.
2. 회차 폴더를 번호순으로 그린다. 생성 직후 새 화를 선택한다. 기본 외부 모드는 설치된 VS Code로 작품 루트와 이번 원고를 연다. 메모장은 파일만 연다. 앱 화면에 현재 파일 경로와 다시 열기 동작을 제공한다.
3. 실행 대상과 인자를 구분한다. 한글·공백·특수문자가 있는 작품도 연다. VS Code 미설치/실행 실패 시 생성된 회차를 유지하고 다른 편집기 선택·다시 열기를 제공한다. 04회에서 내장 쓰기를 연결한다.
4. 연타와 실패 재시도는 같은 생성 의도로 묶는다. 별도의 두 생성 요청은 유일한 연속 번호를 받는다.

### 완료 기준

- [ ] **S03.A** · 0화에서 시작해 1·2·3화를 만든 뒤 다시 열면 순서와 절대 경로가 정상이다.
- [ ] **S03.B** · 동일 요청 재시도는 1개, 독립 요청 두 개는 서로 다른 번호다. 편집기 실패 후 ‘다시 열기’로 회차가 늘지 않는다.
- [ ] **S03.C** · 실제 Windows에서 VS Code 탐색기에 작품 루트가 보이고 편집 영역에 새 원고가 선택된다. 메모장도 같은 원고를 연다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 실제 실행 인자·설정 저장 위치, 생성 재시도 규칙, 설치/미설치 환경에서 확인한 결과.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
