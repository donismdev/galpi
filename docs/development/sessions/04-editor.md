# 04회 · 내장 집필과 한글 입력

**작가가 얻는 결과** · 내장 편집기에서 한글 한 문단을 써서 저장하고 외부에서 같은 파일을 읽는다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 03회에 생성된 본문과 저장 기반이 있다.

### 구현 순서

1. 회차 선택 시 내장 편집기를 실제 파일에 연결한다. 기본 편집기 선택 및 ‘이번만 다른 편집기로 열기’를 구분한다. Markdown 원문, 줄바꿈, 긴 단락, 실행취소, 선택 영역을 보존한다.
2. 입력 시 편집중 → 저장중 → 저장됨/저장 실패 상태를 구현한다. Ctrl+S 즉시 저장, 유휴 자동저장, 문서 전환/창 닫기 시 미저장 처리와 오류 복구를 연결한다. 저장 도중 추가 입력은 새 세대로 관리한다.
3. 한글 조합 중 값 재주입·문서 재마운트를 피하고 조합 종료 후 저장한다. 변경되지 않은 문서를 열기만 해도 BOM·CRLF가 바뀌는지 검사한다. 저장 직전 읽은 버전과 달라지면 보류하고 05회 충돌 흐름으로 확장 가능한 상태를 둔다.
4. 후보 편집기로 Windows 한글 IME가 깨지면 같은 시나리오를 단순 텍스트 편집기로 재현해 원인을 좁히고 실제 통과한 경로를 남긴다.

### 완료 기준

- [ ] **S04.A** · ‘서린은 불씨를 감지했다.’를 실제 IME에서 천천히/빠르게 입력하고 조합 중 저장·포커스 이동·한영 전환 후 누락과 중복이 없다.
- [ ] **S04.B** · Ctrl+S, 자동저장, 마지막 입력 직후 닫기, 저장 권한 실패와 다시 시도를 테스트한다.
- [ ] **S04.C** · 빈 문서 / 장문 / 이모지 / UTF-8 BOM·CRLF를 열고 의도한 문자 외 변경이 없는지 비교한다.

### 추가 지시 (계획 변경분)

원문과 채택 이유는 `docs/development/PLAN_CHANGES.md`에 있다.

- CH1 몫 · 원고 파일이 잠겨 있으면 ‘다시 읽기’를 제공한다. UTF-8 판독 실패에는 ‘원본 위치 열기 / 외부에서 UTF-8 사본으로 저장한 뒤 다시 읽기’를 제공하고, 판독 실패 상태에서는 그 원고의 자동저장을 멈춘다. 기존 앱 초안이 있으면 보존한다.

추가 완료 기준

- [ ] **S04.D** · CP949 한글 원고를 열면 판독 실패 안내가 나오고, 작가가 고르기 전까지 외부 파일 바이트와 기존 초안이 그대로다. 그 동안 자동저장이 일어나지 않는다. 잠긴 파일은 ‘다시 읽기’로 회복한다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 확정 편집기, IME 실측 환경, 저장 상태 전이와 읽은 버전 표식, 미확인 입력 조합.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
