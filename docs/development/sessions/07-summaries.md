# 07회 · 회차 요약·다음 화 메모·퇴고 재확인

**작가가 얻는 결과** · 다음 화를 열 때 어제 남긴 두 줄이 보이고, 원고를 바꾼 뒤 어느 요약을 고쳐야 하는지 안다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 06회의 회차 ID·커밋 ID·비교 화면을 사용한다.

### 구현 순서

1. 회차 요약 루트를 만들고 각 화의 요약을 독립 Markdown으로 저장한다. 목록에는 회차 번호·첫 줄·검토 상태를 표시한다. 요약이 비어 있는 화도 번호가 보인다.
2. 요약과 다음에 쓸 메모를 각각 편집하게 한다. 12화에서 남긴 다음 메모는 13화 만들기 직후 옆에 표시하고, 13화 자체의 요약이나 원고에는 삽입하지 않는다.
3. 작가가 요약을 확인한 커밋 ID를 기록한다. 새 원고 커밋이 생기면 요약에 재확인 표시를 붙이고 이전 확인판과 현재판 비교로 연결한다. ‘수정 후 확인’과 ‘이대로 확인’을 제공한다.
4. 요약 파일을 외부에서 고칠 때도 더 최근인 원고를 자동 확인 처리하지 않는다. 기준판이 없는 경우, 요약 미작성, 초안만 수정된 경우의 상태를 따로 둔다.

### 완료 기준

- [ ] **S07.A** · 1~3화 중 2화 요약이 없어도 2화가 목록에 보인다. 3화 요약을 쓴 뒤 앱을 재실행해도 원문과 상태가 남는다.
- [ ] **S07.B** · 3화 r1 확인 → 원고만 저장 → r2 커밋 → 재확인 → 이대로 확인 순서에서 기대 상태가 정확하다. 1·2화는 영향이 없다.
- [ ] **S07.C** · 12화 메모가 13화 생성 때 한 번 제시되고 같은 파일 내용이 중복 삽입되지 않는다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 요약/다음 메모의 실제 경로, 재확인 계산 규칙, 이후 다른 자료에서 재사용할 검토 인터페이스.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
