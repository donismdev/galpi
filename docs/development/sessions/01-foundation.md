# 01회 · 실행 뼈대와 첫 작업 화면

**작가가 얻는 결과** · 앱을 켜면 네 개의 루트와 언어 전환을 볼 수 있다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 시작 회차. 빈 저장소이거나 기존 저장소에 이 계획만 복사되어 있어도 시작한다.

### 구현 순서

1. 저장소와 기존 빌드 도구를 조사하고 같은 역할의 설정을 재사용해 Tauri 2 + React + TypeScript + Rust 실행 진입점을 만든다. 앱 제품명은 작업용 ‘글쓰기 작업실’로 두고 경로나 파일 규격에 브랜드명을 박아 넣지 않는다.
2. 좌측 네 루트, 빈 메인 화면, 작품 열기 진입 위치를 만든다. 미구현 기능은 클릭 후 조용히 끝나는 가짜 버튼으로 노출하지 않는다. 메뉴·버튼·상태·접근성 이름을 ko/en 리소스에서 읽고 바꾸면 화면에 즉시 반영한다.
3. 프런트 타입 검사·단위 테스트, Rust 검사·테스트, 데스크톱 실행의 실제 명령과 잠금 파일을 마련한다. 저장소 구성과 이번에 실행한 명령을 PROGRESS.md에 남긴다.
4. Windows 실기기에 접근하면 UI 폰트·기본 WebView·한글 입력 가능 여부를 짧게 조사한다. 04회 IME와 16회 교정에 넘길 후보와 검증 환경을 기록한다.

### 완료 기준

- [ ] **S01.A** · 두 언어에서 네 루트가 모두 보이며 앱 재실행 후 선택 언어를 유지한다.
- [ ] **S01.B** · ko/en 키가 하나 빠진 fixture를 넣으면 검사가 어느 키인지 지목한다.
- [ ] **S01.C** · 데스크톱 셸 실제 기동 결과와 브라우저 개발 미리보기 결과를 구별한다. 실기기가 없으면 미확인 항목을 기록한다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 실행 명령, 도구 버전, 루트 컴포넌트·문구 리소스 위치, 첫 실행 화면의 확인 결과.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
