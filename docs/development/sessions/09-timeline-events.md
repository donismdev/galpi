# 09회 · 사건 입력과 회차·작중 시간·함께 보기

**작가가 얻는 결과** · 1화 각성과 3화 능력 변화를 같은 타임라인 안에서 세 방식으로 확인한다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 08회의 카드·태그와 06회의 확정판을 연결한다.

### 구현 순서

1. 타임라인 생성·이름 변경을 제공한다. ‘주인공의 능력’, ‘왕국 연표’처럼 여러 개를 만들고 사건 하나를 공유할 수 있게 한다. 생성 시 기본 모드로 회차 / 작중 시간 / 함께 보기를 고른다.
2. 회차 모드에는 집필한 1~3화를 모두 표시하고 각 행에 ‘사건 추가’를 둔다. 사건에 제목·본문·태그·관련 카드·회차 및 회차 내 순서·선택적 작중 시점을 입력한다. 작품 시간은 트랙명, 정렬 숫자, 자유 표시명으로 받는다.
3. 시간 모드는 트랙과 작중 순서로 읽는다. 함께 보기는 한 행에 사건 하나, 양쪽 좌표를 별도 열에 표시하고 정렬 기준을 선택한다. 좌표 하나만 있으면 반대쪽은 미정으로 표시하고 필터에서 찾을 수 있게 한다.
4. 회차에 연결된 사건은 어느 원고판을 확인했는지 따로 기록한다. 3화 재커밋 후 해당 사건과 요약의 검토 상태를 독립 갱신한다.

### 완료 기준

- [ ] **S09.A** · 1화 ‘각성’, 사건 없는 2화, 3화 ‘불을 다룸’이 정확한 회차에 나타난다. 3화 사건에 작중 좌표를 보탠 뒤 세 보기에서 같은 ID다.
- [ ] **S09.B** · 회차만/시간만/둘 다/모두 비움 입력을 검증한다. 좌표가 모두 빈 사건은 입력 중인 값을 보존하며 수정 안내를 한다.
- [ ] **S09.C** · 한 사건을 두 타임라인에 올려 한쪽에서 고치면 양쪽에서 갱신된다. 두 창 동시 편집의 최종 검증은 14회로 넘긴다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 세 모드의 필터·정렬·빈 좌표 처리, 사건 저장 경로, 공통 표본의 사건 ID.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
