# 18회 · 설치·이전 작품 복구·1.0 판정

**작가가 얻는 결과** · 새 Windows 사용자 환경에서 설치하고 작품 폴더 하나로 원고·자료·이력을 되살린다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 17회 실측 보고서와 이전 회차의 미확인 항목을 검토한다.

### 구현 순서

1. 첫 배포 대상 Windows x64용 설치 파일을 만든다. 버전·빌드 명령·WebView/사전 의존성·설치 경로·배포 표기·체크섬을 기록한다. 개발 도구가 없는 계정/기기에서 실행하고 VS Code 유무 두 경로를 확인한다. 설치 시 필요한 네트워크와 설치 후 오프라인 집필을 구분한다.
2. 초기 버전 형식의 작은 고정 작품과 장편 작품을 복사해 연다. 작품 버전 업그레이드가 실제로 필요한 경우 사전 백업·중단 후 복구를 시험하고, 형식 변경이 없으면 동일 버전 재개와 상위 버전 읽기 보호를 시험한다. 사용 중인 실제 작가 작품은 테스트 데이터로 쓰지 않는다.
3. Q1~Q11과 각 회차의 보류 항목을 원래 사용자 흐름에서 다시 수행한다. 실제 설치 여부, 실제 한글 IME/교정, 외부 편집기, 모니터 분리, 오프라인 실행을 점검한다. 테스트 불가 항목은 재현 명령·필요 환경과 함께 남긴다.
4. 짧은 작가용 시작 안내를 작성한다. 작품 생성, 기본 편집기, 첫 커밋·비교, 첫 타임라인, 구간 링크, 백업/복구, 언어 전환을 설명한다. AI가 확보한 설치 파일과 보고서까지 만들고 공개 배포는 별도 사용자 요청으로 둔다.

### 완료 기준

- [ ] **S18.A** · 새 사용자에서 설치 → 1화 작성 → 2회 커밋 → 사건·설정 연결 → 보조 창 띄우기 → 종료·재실행이 가능하다.
- [ ] **S18.B** · 작품 폴더만 새 위치로 복사해 새 캐시로 열어도 본문·요약·커밋·링크·태그·사전·범위 뷰를 복원한다. 재설치·제거가 작품 파일을 삭제하지 않는다.
- [ ] **S18.C** · 차단 결함·미확인 필수 경로가 있으면 ‘출시 보류’로, 증거가 모였으면 ‘1.0 후보 통과’로 기록한다. 성능 목표 미달은 17회 결과를 인용해 별도로 판정한다.

### 추가 지시 (계획 변경분)

원문과 채택 이유는 `docs/development/PLAN_CHANGES.md`에 있다.

- CH5 · 수동 작품 ZIP 백업과 새 폴더 복원. ‘작품 백업’은 먼저 미저장 초안·미해결 충돌을 알린다. 저장된 작품 전체를 작품 밖의 새 ZIP으로 만들고 파일 목록과 내용 해시를 함께 기록한다. 앱 임시 파일·기기별 캐시는 제외한다. 백업 중 원본이 달라졌거나 일부를 읽지 못하면 불완전한 ZIP을 성공으로 표시하지 않는다. ‘백업 복원’은 새 빈 폴더에서만 하고, 경로·해시 확인 후 작품을 연다. 원래 작품 덮어쓰기는 없다.

추가 완료 기준

- [ ] **S18.D** · 3화 과거판, 직접 쓴 요약, 카드 별칭, 회귀편 링크, 사용자 사전을 백업 → 다른 위치에 복원 → 새 검색 캐시로 다섯 항목을 다시 찾는다.
- [ ] **S18.E** · 백업 도중 원본 파일 하나 변경, ZIP 본문 하나 훼손 → 각각 명확한 재시도/복원 실패 결과. 기존 작품은 그대로 열린다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 설치 파일 경로·버전·체크섬, 실제 실행 환경, 통과/보류 사유, 알려진 한계와 작가용 안내.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
