# 16회 · 한영 교정 밑줄과 언어 완성

**작가가 얻는 결과** · 한국어 소설과 영어 대사를 함께 쓰며 철자·띄어쓰기 제안을 선택 적용한다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 04회 내장 편집기의 IME와 01회 리소스 체계가 확인되어 있다.

### 구현 순서

1. 오프라인에서 동작하는 철자 검사 후보를 실제 지원 OS에서 시험한다. OS/WebView 기능과 배포 가능한 로컬 사전을 실제 혼합 문장에 적용해 범위·오프셋·오탐·재배포 조건을 비교하고 하나를 고른다. 브라우저 spellcheck 속성 설정만으로 통과 처리하지 않는다.
2. MVP 교정 범위는 한·영 철자 제안 및 문맥이 명확한 한국어 띄어쓰기, 영문 비정상 공백 제안이다. 한글 ‘할수 있다 → 할 수 있다’, ‘갈수 있다 → 갈 수 있다’와 ‘물의 수위’, ‘고칠 수 있다’ 대조군을 포함한다. 영문 ‘recieve → receive’, 한국어 ‘됬다 → 됐다’, KO/EN 혼합 문장과 영문 이중 공백을 검증한다. 각 언어의 20개 이상 고정 사례에서 기대 표시·비표시를 명세한다.
3. 밑줄, 후보 보기, 1회 무시, 작품 사전에 고유명사 추가, 개별 제안 적용/실행취소를 제공한다. 작품 사전은 작품 폴더의 버전 있는 파일로 보존한다. 검사 결과에 문서 세대를 붙여 늦은 결과를 폐기하고 IME 조합 중 재주입을 피한다.
4. 사용자 화면·도구 설명·오류·빈 상태·보조 창·접근성 이름의 ko/en 키를 검사한다. ‘English / 한국어’ 전환은 모든 창에 반영하고 교정 언어·사용자 본문은 그대로 유지한다. 사전 배포에 필요한 표기와 자료 출처를 기록한다.

### 완료 기준

- [ ] **S16.A** · 네트워크를 끊은 설치 환경에서 KO·EN 철자, KO 띄어쓰기, EN 공백의 실제 밑줄→제안→실행취소를 확인한다. 검사가 지원되지 않는 범위는 기능표에 정확히 표시한다.
- [ ] **S16.B** · 표본 결과를 언어·철자·공백·정상문·고유명사로 분해해 기대값과 대조한다. 규칙이 추가된 다른 문장도 맞아야 한다.
- [ ] **S16.C** · ‘서린’을 작품 사전에 넣은 후 재실행·작품 폴더 복사에서 유지된다. 다른 작품에는 적용되지 않는다. IME 도중 검사 응답·언어 전환으로 원문이 변하지 않는다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 확정 엔진·사전·라이선스, 실제 제공되는 교정 범위와 예외, 혼합 문장 및 깨끗한 설치 환경 결과.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
