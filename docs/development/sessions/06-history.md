# 06회 · 회차 커밋·판 비교·복원

**작가가 얻는 결과** · 초고부터 마지막 퇴고까지 어느 두 판이든 골라 차이를 본다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 05회에서 외부 변경과 미저장 초안을 구분할 수 있다.

### 구현 순서

1. 회차 커밋 버튼에서 현재 저장 상태를 확인하고, 외부 편집이 있으면 디스크의 최신 원문을 다시 읽는다. 미저장 초안은 저장 후 커밋, 충돌 중이면 05회 해결로 연결한다.
2. 원문 전체·시각·부모·메시지·해시를 회차별 불변 스냅샷으로 게시한다. 동일 요청 ID 재시도는 기존 결과를 돌려주고, 별도 요청이어도 직전 판과 원문이 같으면 ‘변경 없음’을 안내한다. 이 규칙을 UI에도 드러낸다.
3. 이력 목록, 변경 줄 수와 추가/삭제 글자수, 인접판 및 임의 두 판의 문장/단어 내부 강조를 만든다. 글자수는 사용자 인식 문자 단위로 정의하고 비교 정규화·개행 취급을 도움말에 적는다. 한국어 긴 한 문단을 점검한다.
4. 과거판 복원은 현재 작업본 갱신이다. 기존 이력은 그대로 보존하고 다음 확정 시 새 커밋을 추가한다. 현재 작업본이 달라져 있으면 먼저 사본을 확보한다.

### 완료 기준

- [ ] **S06.A** · 1화 r1·r2·r3 생성 후 r1↔r3 비교, 같은 내용 커밋, 다중 클릭, 외부에서 저장한 직후 커밋을 검증한다.
- [ ] **S06.B** · 이력 게시 직전·직후 강제 중단을 각각 재현한다. 재시작 후 이전 또는 완전한 새 판만 정상 이력에 보인다.
- [ ] **S06.C** · 서로 다른 두 회차 이력이 섞이지 않는다. 복원 후 r4가 생겨도 r2·r3 원문과 해시는 보존된다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 커밋 스키마·변경량 계산 단위, 1~3판 실제 시연, 07회가 사용할 최신 revisionId 조회 방법.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
