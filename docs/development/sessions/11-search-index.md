# 11회 · 작품 검색 색인과 외부 수정 반영

**작가가 얻는 결과** · 원고·요약·설정·사건을 한 작품에서 색인하고 원본 파일만으로 재생성한다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 10회까지 생긴 자료 종류와 06회 커밋 원문을 읽을 수 있다.

### 구현 순서

1. SQLite FTS5 trigram 지원을 번들된 실제 앱에서 확인하고, 원문 파일 → 문서 종류/ID/판/문단/태그/회차 → 검색 레코드 변환을 구현한다. 원문 기준 위치와 검색 정규화 문자열의 대응을 보존한다.
2. 제목·별칭·회차번호는 전용 조회, 본문 3글자 이상은 부분 문자열 색인, 1~2글자는 제한 범위의 원문 부분 일치로 처리한다. 메타데이터에서 해당 이름을 못 찾아도 전체 본문의 단독 1글자 결과를 찾게 한다.
3. 해시 비교로 바뀐 문서만 반영하고 삭제·이동·외부 교체·꺼진 동안 수정·작품 복사본을 처리한다. 작업 원고와 과거판을 분류한다. 이력 결과는 별도 옵션에서만 합친다.
4. 백그라운드에서 색인을 만들고 취소/재시작/세대 전환을 분리한다. 깨진 DB·버전 불일치는 재생성한다. 재생성 중 새 변경이 누락되지 않게 순서를 정하고 캐시 삭제 전후 동일 결과를 비교한다.

### 완료 기준

- [ ] **S11.A** · FTS5 가용성과 ‘린/서린/감지했다/불씨/소문자 영문/따옴표/%/_’의 기대 ID를 기록한다. 한 글자 전 범위 검색도 결국 정답을 반환한다.
- [ ] **S11.B** · 한 회차만 외부 수정한 뒤 재색인 대상 수가 해당 자료로 제한된다. 외부 삭제·이름 변경은 유령 결과를 남기지 않는다.
- [ ] **S11.C** · 재색인 중 편집, 앱 종료 후 파일 수정, DB 삭제, 경로만 다른 같은 작품 복사본을 시험한다. 재생성 전후 원본과 이력 해시가 같다.

### 추가 지시 (계획 변경분)

원문과 채택 이유는 `docs/development/PLAN_CHANGES.md`에 있다.

- CH3 몫 · 인물 카드 기준 두 조회의 데이터를 준비한다. (1) 이름·별칭 본문 검색: 선택 카드의 이름·별칭을 문자 그대로 찾고 어떤 이름이 맞았는지 결과에 남긴다(짧은 한글 별칭은 직접 일치 경로). (2) 연결된 회차: 카드 ID와 그 카드에 연결된 사건의 회차 ID로 집계한다. 둘 다 회차 범위로 좁힐 수 있다.

추가 완료 기준

- [ ] **S11.D** · 별칭 ‘린’만 적힌 2화가 이름·별칭 검색에서 ‘린’ 적중으로 나오고, 연결 조회에는 나오지 않는다. 범위 3~3화로 좁히면 2화가 빠진다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · FTS 스키마·토크나이저 설정, 짧은 검색 경로, 캐시 위치·재구축 명령, 기대 결과 fixture.
