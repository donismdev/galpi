# 14회 · 독립 창·참고 패널·배치 복원

**작가가 얻는 결과** · 351화를 쓰면서 직전 화와 능력은 따라오고 300~350화 참고창은 제자리에 남는다.

## AI 작업 지시

이 문서 전체를 이번 회차의 구현 지시로 사용해라. 저장소의 기존 규칙과 `docs/development/FOUNDATIONS.md`, `WORKSPACE_FORMAT.md`, `QUALITY_GATES.md`, `PROGRESS.md`를 확인하고 실제 코드 상태와 대조해라. 네 공통 문서는 모두 `docs/development/` 아래에 있다. 이미 구현한 부분은 동작을 검증해 재사용하고 이번 범위의 코드 수정, 테스트, 인계까지 수행해라.

**시작 조건** · 10회 보기, 12회 대목 이동, 13회 문장 링크가 준비되어 있다.

### 구현 순서

1. 원고·요약·카드·타임라인·저장 보기에서 ‘옆에 열기’와 ‘별도 창’을 제공한다. 같은 문서 화면을 재사용하고 참고창에는 필요할 때만 편집기를 로드한다. 창별 현재 대상·필터·스크롤을 분리한다.
2. 공유 Rust 코어가 활성 집필 회차와 문서 변경을 방송한다. 단순히 참고 문서를 보는 동작이 전체 집필 회차를 바꾸지 않도록 ‘집필 대상으로 열기’를 구분한다. 고정 / 현재 회차 따라가기 / 직전 화 / 현재 능력의 계산을 정의한다.
3. 항상 위, 마지막 위치·크기·모니터·고정/따라가기·대상 ID 복원, 모니터 제거 시 화면 안으로 복귀를 구현한다. 닫은 참고창, 없어진 문서, 다른 작품으로 전환할 때의 정책을 둔다.
4. 두 창이 같은 원고를 쓰면 05회 충돌 처리로 보낸다. 회차 생성·커밋은 모든 창이 같은 요청 경로를 쓴다. 한 창 취소나 닫기가 다른 편집 창의 미저장 작업을 지우지 않게 한다.

### 완료 기준

- [ ] **S14.A** · 351화 + 직전 화 + 현재 능력 + 고정 회귀편으로 구성해 352화로 이동한다. 기대 대상은 352/351/352 기준 능력/기존 회귀편이다.
- [ ] **S14.B** · 참고창에서 327화를 훑어도 현재 집필 회차는 352다. 같은 원고를 두 창에서 고쳐 충돌 후 양쪽 원문을 복구한다.
- [ ] **S14.C** · 배치 저장→재시작, 모니터 분리, 고정 대상 삭제, 창 하나 닫기, 작품 바꾸기를 실제 데스크톱에서 확인한다.

### 회차를 닫을 때

현재 회차에서 추가한 기능을 앱의 정상 진입점으로 한 번 따라가라. 실제로 실행한 명령·환경·결과를 `docs/development/PROGRESS.md`에 적고, 실행하지 못한 실기기 검사는 필요한 환경과 함께 ‘미검증’으로 남겨라. 임시 작품·합성 원고로 테스트하고 사용자의 실제 원고를 바꾸지 마라.

**이번 회차 인계 항목** · 창별/작품별 상태 표, 실제 4창 시연 환경, 복원 실패를 처리한 결과.

최종 답변에는 작가가 따라 할 확인 절차, 변경 파일, 완료 기준별 통과/실패/미검증과 남은 영향을 적어라. 다음 개발 회차는 별도 지시에서 진행한다.
