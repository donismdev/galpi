# 인수 시나리오와 성능 목표

## 공통 소설 표본

작품명은 ‘잿빛 항구’. 1화에서 서린이 각성한다. 2화에는 사건이 없다. 3화 초고에는 ‘서린은 손끝에 불을 피웠다.’가 있고 퇴고 후에는 ‘서린은 남은 불씨를 감지했다.’로 바뀐다. 7화에 검은 편지가 등장하고 32화에서 발신자가 밝혀진다. 300~350화는 과거 회귀, 327화는 본편 10일차보다 앞선 작중 2일차다. 351·352화는 연재 현재로 돌아온다. 동일 인용 두 개, 별칭 ‘린’, 한글·영문·이모지·CRLF 원고, 공개 회차가 없는 비공개 사건과 작중 시점 미정 사건도 포함한다. 소규모 회차별 표본에서 필요한 부분만 생성하고, 17회에 고정 난수 시드로 장편 표본을 만든다.

| 번호 | 실제로 해야 할 일 | 통과 증거 |
|---|---|---|
| Q1 | 빈 폴더 지정 → 1화 생성 → VS Code/기본 내장/Windows 메모장으로 열기. VS Code가 없을 때도 같은 원고에서 계속 진행 | 생성된 실제 경로·파일 수, 외부 편집기 수동 확인, 재시도 후 동일 ID |
| Q2 | 같은 원고를 외부와 앱에서 각각 고치고 충돌 대화상자에서 종료한 뒤 앱을 다시 열기 | 양쪽 텍스트와 복구 선택지가 남음. ‘저장 실패’와 ‘저장됨’이 구별됨 |
| Q3 | 초고·퇴고·3차 커밋 후 최초와 마지막 직접 비교. 오래된 판을 새 작업본으로 복원 | 추가·삭제·변경량, 이력 3개 유지. 복원 뒤 커밋하면 4번째 이력 생성 |
| Q4 | 회차 요약과 능력 사건을 r1 기준으로 검토 → 원고 r2 확정 → 각각 다시 확인 | 관련 자료만 표시. 요약 확인이 사건 경고를 끄지 않음. 확정 전 초안과 구분 |
| Q5 | 회차순·시간순·두 축 보기. 범위에 300·350 포함, 299·351 제외. 태그 숨긴 뒤 복원 | 원본 사건 수 불변. 기존 구간 링크에서 새 327화 사건이 즉시 보임 |
| Q6 | 25화 독자 기준과 작중 2일차를 각각 조회. 나중에 공개되는 과거 사건과 공개 회차 미정 사건을 포함한 데이터 사용 | 독자 모드에 미래 설정 누출 없음. 작중 모드는 해당 트랙의 알려진 좌표로 조회. 각각 기대 사건 ID와 일치 |
| Q7 | ‘린’, ‘서린’, ‘불씨’, ‘손끝에’, 영문 대소문자, 따옴표·%·_ 검색. 작업 원고에는 사라진 문장을 이력에서 찾아가기 | 기대 문서·버전·대목 적중. 캐시 제거 후 재생성 결과 동일. 필터와 취소 동작 |
| Q8 | 351화 편집 + 직전 화 + 고정 회귀 구간 + 현재 능력 창. 352화 이동, 재시작, 보조 모니터 제거 | 고정과 따라가기 동작이 구분됨. 화면 밖 창이 복구됨. 원고 전체의 중복 로딩 여부 측정 |
| Q9 | IME 조합 도중 자동저장·검색 응답·교정 응답이 도착. 한국어/영어 전환, 혼합 문단 제안 적용 후 실행취소 | 글자 누락·중복·커서 점프 없음. 본문 언어·내용 불변. 늦은 교정 결과가 새 원고를 바꾸지 않음 |
| Q10 | 복선 닫기/다시 열기, 인용의 앞에 문단 삽입 후 찾기, 동일 인용 두 군데, AI 자료 미리보기 후 복사 | 정확한 원문으로 이동. 모호하면 후보 선택. 복사 내용과 미리보기 동일, 미래·제외 자료 불포함 |
| Q11 | 앱을 새 Windows 사용자에 설치 → 작품 폴더만 복사해 복구 → 앱 교체·재설치 | 이전 수정 이력, 링크, 요약, 템플릿, 태그, 타임라인 모두 보존. 설치 파일·버전·실행 환경 기록 |

## 17회에서 실제로 잴 예산

아래 수치는 설계 목표다. 개발 환경·빌드·디스크·메모리를 명시하고 release 빌드에서 측정한다. 기준 장비 예시는 Windows x64, SSD, RAM 16GB다. 다른 장비 결과는 분리해 적는다. 작은 표본에서 수치를 추정해 통과 처리하지 않는다.

| 환경과 조작 | 잠정 목표 | 측정법 |
|---|---|---|
| 1,000화 × 한글 약 5,000자, 사건 10,000개, 화당 과거판 3개 | 검색·창 전환 검증용 기준 작품 | 고정 시드, 정답 목록, 총 바이트, 생성 명령 기록 |
| 예열 후 Ctrl+P / 일반 3글자 이상 본문 검색 | 첫 유효 결과 P95 100ms / 250ms 이내 | 30회 이상. 키 입력부터 화면 표시까지, 디바운스 포함. 범위·검색어 분포 고정 |
| 한두 글자 검색 | 첫 페이지 P95 500ms 이내, 진행 중에도 입력·취소 가능 | 흔한 글자·드문 이름·0건을 분리. 취소된 요청의 결과가 새 화면을 덮으면 실패 |
| 네 창을 연 상태의 타이핑 | 조합 중 데이터 손실 0, 입력→다음 화면 갱신 P95 50ms 이내 목표 | 한글 IME 실기기 확인 + 타이밍 기록. 색인 재생성 중에도 별도 측정 |
| 첫 실행 / 캐시 있는 재실행 | 첫 색인 중 편집 가능. 예열 재실행 후 집필까지 2초 목표 | 콜드/웜, 첫 색인 총 시간·디스크 크기, 1개/4개 창 총 메모리·창당 증가량 기록. 메모리 상한은 첫 기준선으로 결정 |

미달은 관측 조건·느린 구간·수정 전후 결과를 남긴다. 데이터 손실, 무음 덮어쓰기, 사라진 커밋, 독자 기준 미래 누출은 출시 차단이다. 숫자 목표 미달은 영향과 실측을 공개해 출시 여부를 판단하며 임계치를 뒤에서 바꾸지 않는다.
