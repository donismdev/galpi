# 글쓰기 작업실 개발 계획 · 18회차

**첫 목표는 06회에 실제 원고 한 편을 쓰고, 고치고, 되돌아보는 것이다.** 10회에는 회귀 구간 링크와 시점별 설정 조회, 14회에는 여러 창을 활용하는 장편 집필, 18회에는 Windows 설치·복구 검증까지 끝낸다.

‘회차’는 여기서 **AI에게 한 번에 맡길 개발 단위**다. 작품의 1화·2화와 구분한다. 예상 일수는 정하지 않았다. 각 회차의 통과 조건이 다음 작업의 출발점이다.

## 바로 시작하기

1. ZIP을 앱을 개발할 저장소 루트에 푼다. `docs/development/FOUNDATIONS.md`가 보이는 위치면 맞다. 기존 동명 문서가 있다면 그 내용을 먼저 보존하고 합친다. 이 단계에서 작가의 작품 폴더를 만들 필요는 없다.
2. 코딩 AI에서 **그 저장소**를 열고 아래 첫 지시를 붙여 넣는다. 저장소를 받지 못하는 채팅이라면 기초 설계·데이터 계약·품질 기준과 해당 회차 카드를 함께 전달한다. 실제 코드 접근·실행이 가능한 환경이어야 구현과 검증을 완료할 수 있다.
3. 회차가 끝나면 `docs/development/PROGRESS.md`에서 실제 결과와 증거를 확인한다. 다음 대화는 같은 저장소에서 해당 회차 파일 하나를 지정해 시작한다. 한 대화에서 가능한 범위를 넘으면 같은 회차의 미완료 항목부터 재개한다.

**첫 지시**

```text
이 저장소의 docs/development/sessions/01-foundation.md를 열고 이번 회차 작업 지시로 실행해줘.
프로젝트 규칙과 기초 설계를 확인하고, 구현·검증·PROGRESS.md 인계 기록까지 마쳐줘.
다음 회차는 시작하지 말고, 이번에 내가 직접 켜서 확인할 동작과 실제 테스트 결과를 알려줘.
```

**중단된 회차를 이어갈 때**

```text
docs/development/PROGRESS.md에서 진행중인 회차와 마지막 검증 결과를 확인해줘.
해당 sessions 파일의 완료 기준 중 남은 항목부터 이어서 구현하고, 완료 여부와 재현 방법을 기록해줘.
```

각 회차 카드 **전문**이 AI에게 줄 프롬프트다. 카드를 읽을 수 있는 코딩 AI에는 경로만 지정해도 된다. 공통 문서와 회차별 인수 조건은 나중에 작업자가 바뀌어도 유지한다.

## 18회차 지도

| 개발 회차 | AI가 맡을 작업 | 작가가 직접 확인할 결과 |
|---|---|---|
| 01 | 실행 뼈대와 첫 작업 화면 | 앱을 켜면 네 개의 루트와 언어 전환을 볼 수 있다. |
| 02 | 작품 폴더 열기와 안전한 저장 기반 | 빈 폴더로 시작하고 기존 작품을 다시 열어도 작가 파일이 보존된다. |
| 03 | 다음 화 생성과 외부 편집기 | ‘다음 화 쓰기’ 한 번으로 새 원고와 작품 폴더가 VS Code에 열린다. |
| 04 | 내장 집필과 한글 입력 | 내장 편집기에서 한글 한 문단을 써서 저장하고 외부에서 같은 파일을 읽는다. |
| 05 | 외부 변경·충돌·초안 복구 | 앱과 VS Code가 같은 회차를 고쳐도 작가가 쓴 양쪽 문장을 다시 꺼낼 수 있다. |
| 06 | 회차 커밋·판 비교·복원 | 초고부터 마지막 퇴고까지 어느 두 판이든 골라 차이를 본다. |
| 07 | 회차 요약·다음 화 메모·퇴고 재확인 | 다음 화를 열 때 어제 남긴 두 줄이 보이고, 원고를 바꾼 뒤 어느 요약을 고쳐야 하는지 안다. |
| 08 | 세계관 카드·범용 템플릿·사용자 태그 | 캐릭터·성격·장소·세계 규칙을 한 번 눌러 만들고 작가 자신의 분류로 찾는다. |
| 09 | 사건 입력과 회차·작중 시간·함께 보기 | 1화 각성과 3화 능력 변화를 같은 타임라인 안에서 세 방식으로 확인한다. |
| 10 | 회귀 구간 링크와 그 시점의 능력 | 300~350화만 보는 링크를 저장하고 독자가 25화까지 아는 능력을 조회한다. |
| 11 | 작품 검색 색인과 외부 수정 반영 | 원고·요약·설정·사건을 한 작품에서 색인하고 원본 파일만으로 재생성한다. |
| 12 | 빠른 열기와 본문 대목 검색 | 단축키로 351화·인물·회귀편을 열고, 사라진 문장을 옛 원고에서 다시 찾는다. |
| 13 | 문장 연결·역링크·복선 회수 | 설정에서 근거 문장으로 돌아가고 아직 회수하지 않은 복선만 본다. |
| 14 | 독립 창·참고 패널·배치 복원 | 351화를 쓰면서 직전 화와 능력은 따라오고 300~350화 참고창은 제자리에 남는다. |
| 15 | AI 참고 자료 선택과 복사 | 36화를 쓰기 전에 최근 5화 요약·등장인물·미회수 복선을 한 번에 복사한다. |
| 16 | 한영 교정 밑줄과 언어 완성 | 한국어 소설과 영어 대사를 함께 쓰며 철자·띄어쓰기 제안을 선택 적용한다. |
| 17 | 장편 1,000화 부하·검색 정확도·복구 측정 | 장편에서 답이 맞는지와 작가가 기다리는 시간을 같은 빌드에서 잰다. |
| 18 | 설치·이전 작품 복구·1.0 판정 | 새 Windows 사용자 환경에서 설치하고 작품 폴더 하나로 원고·자료·이력을 되살린다. |

**의존 관계.** 진행 순서는 01→18이다. 06회의 커밋 ID는 07·09·13회의 ‘재확인’ 기준이다. 09회의 사건 ID와 두 좌표는 10회 시점 조회와 15회 AI 자료 선택에 쓰인다. 11회는 검색 데이터, 12회는 사용자가 실제 문장까지 도달하는 화면이다. 14회는 각 창에서 같은 저장·조회 경로를 사용하며, 17·18회는 출시 판단에 필요한 실측과 복구 증거를 남긴다.
